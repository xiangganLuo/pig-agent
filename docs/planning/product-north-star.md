# pig-agent 产品北极星（2026-07-15 用户拍板）

> 这是产品的"魂"。所有后续研发/评审都以此为准绳。

## 一句话定位

**pig-agent 是一个 24 小时不停转、站在 Claude Code 之上的"超级助手"——它有自己的大脑（多协议模型层），编排 CC 去干编程的活，通过多种渠道随时触达人，自己专注于"解决人的事情"。**

## 两个底层特征（贯穿一切）

- **常驻 · 24h 不停转**：不是"按需唤起的会话工具"，而是持续在线、无人值守替人办事——数字员工 + 定时/cron + 记忆让它在人下班后仍推进（如今夜）。这从根本上区别于"每次为编程而唤起"的 CC。
- **多渠道触达人**：与人的沟通方式未来会有很多，**channel 只是其中之一**。人机交互是一等公民、可插拔扩展的入口面（飞书/钉钉/CLI 只是当前实现，未来还会更多），设计上必须保持"再加一种触达方式 = 加一个渠道策略"的可扩展性。

## 三个"外包"，一个"专注"

pig-agent 不什么都自己做。它把复杂的、别人已做到极致的东西**交出去**，只把力气花在自己的差异化上。

| 层 | 谁来做 | 理由 |
|---|---|---|
| **底层 harness**（权限/记忆/压缩/中断/沙箱/事件/session/sub-agent/plan mode） | **AgentScope Java 2.0 原生** | 基础设施是"复杂的东西"，交给框架。这正是 v2 全量迁移的战略动因——腾出手专注定位 |
| **编程执行**（写代码、跑测试、改仓库） | **编排 Claude Code** | CC 在编程界近乎垄断，不与其正面竞争；把编码任务**委派给 CC**执行 |
| **模型能力** | pig-agent **自己的大脑** | 多协议模型层（5 个 `ModelProtocol`）是独立大脑，不绑定单一供应商、不依赖 CC 的模型 |
| **专注 → 解决人的事情**（编排 + 人机交互 + 事务自动化） | **pig-agent 核心** | 这是唯一要自研到极致的地方 |

## pig-agent 是什么（差异化，自研到极致）

- **编排层**：把 CC、其他专业 agent、工具、MCP 编排起来完成"人的目标"。pig-agent 是指挥，不是又一个执行编码的手。
- **人机交互层**：channels（飞书/钉钉/…是"人"的入口）、CC 风格 REPL/中文 UX、数字员工三段式晨报——面向"人"，不是面向开发者终端。
- **自己的大脑**：多协议、多模型管理、运行时切换、fallback——供应商无关的智能底座。
- **替人办事**：数字员工 + 定时/cron + 记忆 + 技能——无人值守地把人的事务办掉。

## pig-agent 不做什么

- ❌ 不做"又一个终端编码 agent"和 CC 抢编程。编程 → 编排 CC。
- ❌ 不自研底层 harness（迁 2.0 原生）；自研的 RetryingModel/CompressionService/权限 Hook/SessionManager 等在 v2 里能删则删。
- ❌ 不重造 CC/框架已有的能力。

> **评审准绳**：每个新特性问一句——**它在强化"编排 / 解决人的事情 / 自有大脑"，还是在重造 CC 或 harness 已有的东西？** 后者不做。

## 对路线的影响（重排优先级）

1. **AgentScope 2.0 全量迁移** —— 战略级、被本定位强validated（外包 harness 的载体）。长线推进，见 `agentscope-v2-migration.md`。
2. **旗舰新方向：CC 编排能力**（`cc-orchestration`）—— 把 Claude Code 作为被编排的子 agent/CLI/工具，pig-agent 接到"帮我改代码/建项目"这类意图时，规划 → 委派 CC 执行 → 汇总结果给人。**这是把"CC 之上的超级助手"落地的关键一跳，应作为迁移后的头号自研方向。**
3. **保留强化**：channels（人的入口）、数字员工/定时、记忆、技能、编排/多 agent、多协议大脑、中文 UX、`/ls` 流水线。
4. **弱化/外包**：与"编程终端 agent"竞争的自研（自研 shell/沙箱仍留作通用自动化底座，但不是重点）；底层 harness → 2.0。
5. **今夜在跑的 A1-A5,A8**：多为跨切面质量（循环检测/按需工具/记忆/上下文/技能），**服务于"编排 + 助手"，与新定位一致**，继续交付；其中偏"编码 agent"的沙箱项仅作通用自动化底座保留。
