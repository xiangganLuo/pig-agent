# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Pig Agent is a terminal-based AI agent framework for Java, built on **AgentScope Java 2.0** (`agentscope-core` + `agentscope-harness` + `agentscope-extensions-model-*`, all `2.0.0`). Each agent wraps AgentScope's **`HarnessAgent`** vehicle — which delegates to a `ReActAgent` (`HarnessAgent.getDelegate()`) — and is exposed through a picocli + JLine3 REPL, with pluggable LLM providers, multi-model management, independent conversation sessions, a two-tier memory model, automatic context compression, built-in tools, MCP integration, native subagent delegation, Plan Mode, task scheduling, and message channels. The undifferentiated plumbing (permission, state/sessions, retry/interrupt, hooks-as-middleware, tool-result eviction, subagents, Gateway, Plan Mode) is now the framework's native 2.0 machinery; pig keeps its differentiators on top (see **Migration to 2.0** below).

The README (in Chinese) is a detailed reference for the original architecture; this file is the source of truth for the current build and module layout.

> **Migration to 2.0 (done).** The whole reactor runs on pure AgentScope 2.0 artifacts — no 1.x `io.agentscope:agentscope` dep, no deprecated `io.agentscope.core.hook.*` — and the v1→v2 migration was promoted to `main`. The authoritative, per-phase execution log (POM→2.0; native permission `PermissionEngine`+`PermissionContextFactory`; native state `AgentStateStore`+`RuntimeContext`; native retry/interrupt; hooks→`MiddlewareBase`; the `HarnessAgent` vehicle; native subagents; tool-result eviction; Gateway; Plan Mode; the P0 `GuardedAgentTool extends ToolBase` fix) is `docs/planning/agentscope-v2-migration.md` (§1–§16); the REPLACE/KEEP/ADAPT/GAP ledger + delivery summary are `docs/planning/harness-capability-map-2026-07-16.md` and `docs/planning/v2-migration-delivery-2026-07-16.md`. For the 2.0 API authority use the **`agentscope-expert`** skill (`.claude/skills/agentscope-expert/`). The v1 (1.0.12) line is archived at branch `v1-stable-20260716` + tag `v1-final-20260716` (also `v1.0.12-final`).

## Build & Run

```bash
mvn compile                       # compile all modules
mvn test                          # run all tests (offline; jacoco instruments but does NOT gate here)
mvn verify                        # tests + jacoco per-module coverage-floor gate (ratchet); *IT stay skipped
mvn verify -Pit                   # also run the real-model *IT (needs a configured models.json)
mvn install                       # build + install to local repo
mvn exec:java -pl pig-agent-cli   # run the CLI REPL (main: io.pigagent.cli.PigAgentCli)
mvn -pl pig-agent-cli -am compile # compile the CLI and everything it depends on
```

> **CI quality gate (`ci-quality-gate`):** `mvn verify` enforces a **per-module jacoco line-coverage floor** (a ratchet set at "current − 2%", so coverage can't regress; stock jacoco has no cross-module aggregate `check`). `maven-failsafe-plugin` runs the `*IT` real-model tests only under `-Pit` (or `-DskipITs=false`); a credential-less `mvn verify` skips them and stays green.

Run a single module's tests, or a single test class/method:

```bash
mvn test -pl pig-agent-model
mvn test -pl pig-agent-config -Dtest=ConfigurationManagerTest
mvn test -pl pig-agent-task -Dtest=TaskTest#methodName
```

Requires **Java 17** and Maven 3.9+. Models are configured **interactively on first run** (the onboarding wizard writes `~/.pig-agent/workspace/models.json`) and stored there going forward — API keys are no longer read only from the environment, though env vars (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `DASHSCOPE_API_KEY`, `GEMINI_API_KEY`, `MIMO_API_KEY`; Ollama needs none) still work as a fallback. With no usable model, the wizard runs and cannot be skipped.

> The README's build commands show a trailing `-s ` settings flag — that is a stale leftover; no custom Maven settings file is used. Use the plain commands above.

### Model protocol extensions
The provider module is organized by **protocol standard**, not vendor: 5 `ModelProtocol` implementations (`openai` / `anthropic` / `gemini` / `ollama` / `dashscope`) over the AgentScope 2.0 model classes `io.agentscope.extensions.model.<p>.<P>ChatModel` (builder API `.apiKey/.modelName/.baseUrl/.build` — unchanged from 1.x). Any OpenAI-compatible vendor (Xiaomi mimo, DeepSeek, Kimi, Qwen-compat, …) is reached through the `openai` protocol + that vendor's base URL — no per-vendor class. `pig-agent-providers/pom.xml` depends on the five `agentscope-extensions-model-{openai,anthropic,gemini,ollama,dashscope}` (`2.0.0`); **each extension bundles its vendor SDK transitively** (anthropic-java, openai-java, google-genai, dashscope-sdk-java), so the explicit 1.x SDK declarations were removed from that module. The DashScope extension's bundled `slf4j-simple` is excluded there to keep Logback the sole binding. (The parent POM still pins the vendor-SDK versions in `dependencyManagement` — harmless, unused-by-classpath leftovers from the 1.x setup.)

### Embedding model layer (`embedding-model-layer`, E0)
An **embedding model** is a first-class stored category alongside chat models: `StoredModel` carries a `ModelKind` (`CHAT` default | `EMBEDDING`) and `ModelStore`/`models.json` keeps an independent **default-embedding-model pointer** (`defaultEmbeddingModelId`) next to the default chat model. AgentScope 2.0 has **no embedding `Model` API** — an embedding model is *not* built via `ModelProtocol.createModel` (that builds a chat `Model`); it is an OpenAI-compatible `/embeddings` endpoint consumed by `OpenAiCompatibleEmbedder` (raw HTTP behind its `HttpPost` seam), so the same `openai`-compatible protocol + baseUrl serves both chat and embeddings (the `/embeddings` path is an embedder detail). **Back-compat:** an old `models.json` entry with no `kind` reads back as `CHAT`, and deleting the default embedding model clears the pointer. **Connectivity test:** `ModelManager.test` dispatches by kind — a chat model issues a tiny chat ping; an embedding model issues one `embed("ping")` `/embeddings` probe — through the same bounded-timeout + credential-redacted `runProbe` (generic over the probe's result type); the mapping is offline-tested via an injectable embedder seam, the live `/embeddings` round-trip is deferred to `/ls:itest`. **UX:** `/model add` chooses the kind (embedding needs a model name; the first embedding model auto-becomes the default embedding); `/model list` annotates `(embedding)` + `[default-embedding]`; `/model set-embedding <id|index>` sets the pointer; `OnboardingWizard` offers an optional, skippable embedding step after the mandatory chat model (declining = chat-only, unchanged). Credential hardening is reused (masked entry, `0600`, never echoed). **`resolveEmbedder`** (in `AgentBootstrap`, consumed by `hybrid-memory-search`/`memory-retrieval-injection`) resolves in order: explicit config `embedder-model-id` → store default-embedding pointer → `null`; it builds the embedder from whatever the id resolves to (kind not required, so a legacy `embedder-model-id` pointing at a chat model keeps working). **Default: no embedding model configured → `resolveEmbedder` returns `null` → BM25-only memory search (today's behavior, zero regression).** E0 only *supplies* the resolved embedder — flipping the default retrieval path from BM25-only to hybrid is the follow-up **M-B**, not E0. Change: `openspec/changes/embedding-model-layer/`.

## Architecture Essentials

**Wiring happens in `AgentBootstrap.build(...)`** (`pig-agent-cli`) — workspace, config, providers, model store/manager, the shared native `JsonFileAgentStateStore` (root `workspace/state/`), the native permission context (`PermissionContextFactory`), the pig middleware list, the agent + kernel, sessions, compression, tasks, the channel agent, outreach, and MCP are all constructed and connected there, returned as an `AgentBootstrap.Services` holder. Read it first to trace how a component plugs in. **The CLI REPL is the primary frontend**, adding its own surface on top of `Services`: `PigAgentCli.main` (REPL + channel bridges + optional Web console). The embedded Web console lives in the `pig-agent-web` module — a second `AgentKernel` adapter (HTTP + SSE over the kernel façade), started in-process when `web.enabled` (default off), sharing the one kernel with the REPL. "Add a frontend = add an adapter" now has two live examples (REPL + web).

**System prompt assembly (`system-prompt`).** The agent's system prompt is assembled in `AgentBootstrap.build` as `sysPrompt = workspace.readAgentMd() + "\n\n" + workspace.readInfoMd() + AgentBootstrap.TOOL_GUIDANCE`. `AGENT.md` is a **user-editable template** seeded once per workspace by `WorkspaceManager.defaultAgentMd()` via `createIfAbsent` (only new workspaces get the default; an existing user's `AGENT.md` is never overwritten). The seeded default is a **detailed, structured, English production-grade prompt** — sections for identity, operating principles, tool discipline (the real tools: `readFile`/`writeFile`/`listDirectory`, `executeCommand`, `fetchUrl`/`webSearch`, tasks/checklists, compute tools, MCP self-mgmt), skills (`listSkills`/`loadSkill` + the 7 built-in skills), safety/permissions & sandbox awareness, planning, output conventions (**reply in the user's language**), and error handling; it names only real tools/plugins/skills. `INFO.md` carries per-machine env. `TOOL_GUIDANCE` is a fixed release-owned constant (byte-stable per run) appended even when a user rewrites `AGENT.md`, so the always-on constraints survive: native-path file tools over the shell, graceful degradation when a tool is confirmed/denied/unavailable, and never echoing credentials. Change: `openspec/changes/system-prompt-optimization/`.

**The agent vehicle = `HarnessAgent` (`av2` Phase 5b).** `PigAgent` wraps a `HarnessAgent` built **directly** via `HarnessAgent.builder()…build()` (not `fromAgent(...)`, which would triple-copy the toolkit and could drop pig's middlewares) — carrying pig's exact `Toolkit` / middlewares / `stateStore` / `permissionContext` / `maxRetries` / `fallbackModel` / `maxIters`. Turn methods (`call`/`stream`/`streamEvents`, `setPermissionMode`, Plan Mode) run through the **vehicle** (so native **tool-result eviction** applies); conversation-state ops (`getAgentState`/`saveAgentState`, `interrupt`, `ConversationMemory`, and the `getReactAgent()` test seam) run through the **delegate** = `harness.getDelegate()` (the exact `ReActAgent` the vehicle uses). At build, pig **`disableXxx()`s every batteries-included harness extra it already owns** — `disableFilesystemTools`/`disableShellTool` (pig's guarded FS + command sandbox), `disableMemoryTools`/`disableMemoryHooks` (pig's ephemeral prefix-cache memory + A4 extraction), `disableCompaction` (pig's A5 context-engineering), `disableWorkspaceContext`/`disableAtPathExpansion` (pig assembles its own byte-stable system prompt), `disableDynamicSkills`/`disableDefaultWorkspaceSkills`/`disableToolsConfig`/`disableSessionPersistence` — turning ON only tool-result eviction (+ subagents/Plan Mode when enabled). `PigAgent`'s public surface is unchanged, so cli/web/channel/kernel are untouched.

**The agent is swappable at runtime.** AgentScope's `Model` is fixed at build time, so to switch models without restarting, the `PigAgent` is built via `AgentFactory.create(model)` and stored in a mutable `AgentHolder`. Everything (REPL, channels, session manager, compression) reads the current agent through the holder. `ModelManager.ensureModel(...)` rebuilds the agent on a model switch; per-session conversation survives the rebuild because every rebuilt agent shares the one `JsonFileAgentStateStore`.

**Peer agents (`agent-management`; distinct from subagents — see below).** The single `AgentHolder` is driven by an `AgentRegistry` (`Map<agentId, AgentInstance>`): the holder is a **live view of the active instance**, so every existing reader stays unchanged. A **peer** is the *active* agent you switch to (long-lived, `/agent use`), as opposed to a **subagent** (a transient child the active agent delegates to — see **Native subagents**). Each peer is a declarative, immutable `AgentSpec` — its own model (`modelId` → `ModelManager.modelFor`, fault-tolerant fallback to default), tool subset (`AgentWiring.toolkitFor` = `Toolkit.copy()` + `removeTool` by whitelist), and permission mode (a per-agent native `PermissionContextState` via `PermissionContextFactory`, agent-mode override else global) — persisted at `workspace/agents/{id}.md` (`AgentSpecRepository`, YAML front-matter + prompt body) and built by `AgentInstanceFactory` (per-agent toolkit/middlewares/memory + permission context; NOT the shared `AgentFactory`). On an empty `agents/`, a `default` instance equivalent to the old single agent is bootstrapped, so single-agent behavior is unchanged. Operate via `/agent list|use|new|model`. Design: `docs/design/agent-management-design.md`.

**Kernel façade (`AgentKernel` + `KernelEvent`, `agent-kernel-facade`).** The frontend drives the kernel through the single `io.pigagent.core.agent.kernel.AgentKernel` façade — `listAgents/getAgent/activeId/useAgent/createAgent/updateAgent/deleteAgent/chat/runNow/interruptCurrent/subscribeEvents` — and depends **only** on it, never on the internal `AgentRegistry`/`AgentInstanceFactory`/`AgentSpecRepository`/`AgentRunner` (the façade orchestrates those). "Add a frontend = add an adapter": `PigAgentCli.main` builds one `AgentKernel` and injects it into `AgentRepl`; `ReplContext` exposes only the kernel and `AgentCommand` (`/agent …`) calls through it. A REPL chat turn streams via `kernel.chat(activeId, msg, sessionId)` → `Flux<io.agentscope.core.event.AgentEvent>` (the native typed event stream; the old single-arg `stream(Msg): Flux<Event>` is gone). `chat` registers an interruptible `TurnHandle`, so mid-turn Ctrl-C → `kernel.interruptCurrent()` drives native `ReActAgent.interrupt(RuntimeContext)` (cooperative, checked at reasoning-step boundaries) + `takeUntilOther` so the frontend regains control immediately. Pig's own **lifecycle** events (`KernelEvent`: `AGENT_CREATED/DELETED/SWITCHED`, `CHAT_STARTED`, `RUN_STARTED/FINISHED`, `REPORT`) are a separate pig channel published on a `Sinks.many().multicast()` hot `Flux` via `subscribeEvents()` — no subscribers = zero cost. **Channels are a façade-visible separate track (D4):** each channel keeps its own `channelHolder` + channel-mode permission agent and is **not** a switchable kernel agent (that would leak the no-confirmer channel agent into `/agent use`); `ChannelAgentBridge` takes an optional `AgentKernel` and calls `noteChannelChat(channelId)` so channel turns surface as `CHAT_STARTED` events tagged `channel:<id>` — visible, not owned.

**CC-style REPL rendering (`tui-frontend`, capability `cc-repl`).** The REPL is a Claude-Code-style **line-based** conversational front-end (never full-screen). A chat turn streams via `kernel.chat` → `Flux<AgentEvent>` and `AgentRepl.renderStream` aggregates the typed events — answer from `TextBlockDeltaEvent.getDelta()`, tool blocks from `ToolResultTextDeltaEvent`/`ToolResultEndEvent` (`getState()==DENIED` shown as a denial), an animated thinking spinner on `ModelCallStartEvent`/`ThinkingBlockStartEvent` (see below), `ExceedMaxIters`/`AllToolsDenied` notices, subagent `source`-tagged events, and it returns any `RequireUserConfirmEvent` for the **HITL confirm loop** (see permissions) — rendered by `repl/render/`: `MarkdownAnsiRenderer` (pure `**bold**`/`` `code` ``/```` ``` ````-fence/`- list`/`# heading` → ANSI), `StreamingMarkdownPrinter` (flushes each complete answer line as its newline arrives, tracking fenced-code state across chunks), and `ToolCallFormatter` (tool calls render as `⏺ toolName` / `  └ result summary`, single-line + truncated, with `redact(...)` masking `sk-`/`key=`/`Bearer` secrets — credentials MUST NOT appear in REPL output). Reasoning shows an **animated** thinking spinner (`repl/ThinkingSpinner` + pure `render/Spinner`): a braille glyph `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` cycling on a single-daemon `ScheduledExecutorService` (~90ms) + `thinking…` + elapsed seconds (`⠹ thinking… (3s)`), started on `ModelCallStartEvent`/`ThinkingBlockStartEvent` and **stopped + line-cleared** (`\r` + ANSI erase) when the first answer text/tool call/tool result/agent-end/confirm arrives — all repaints and the stop run under one lock (and the render loop stops it before printing any real line), so animation never interleaves with output. It animates **only on a real interactive TTY** (reuses `InlineSelector.isInteractive` — the slash-completion gate) and can be turned off via `repl.spinner` (default on); a non-TTY/redirected terminal degrades to a single static `⋯ thinking` line (today's behavior, no `\r` spam). A one-line `StatusLine` (`model · session · perms`, model via `StoredModel.label()`, no credentials) prints above each prompt. `repl/select/` provides an arrow-key inline picker (`InlineSelector` + pure `SelectorModel`); `/model` with no args pops it (Enter selects, Esc/q cancels), degrading to numeric input on a non-interactive terminal, then `ModelSelection.apply` tests + activates the model.

**REPL flow:** `AgentRepl` builds a JLine `Terminal` (jna provider, `jansi(false)`) and a picocli command tree (`ReplCommands`) via `picocli-shell-jline3`. A line starting with `/` is dispatched to a picocli subcommand (`/model`, `/agent`, `/session`, `/mcp`, `/permission`, `/plan`, `/memory`, `/compress`, `/notify`, `/tasks`, `/status`, `/help`, …) — typing `/` **auto-pops** a completion menu covering **all** commands (picocli metadata via `SystemRegistry.completer()`) with no Tab: `SlashCompletionWidgets` overrides the printable-range `self-insert`/`backward-delete` to re-run `expand-or-complete` after each keystroke **only while the buffer is a slash command** (pure gate `SlashCommands.isCommandBuffer` + non-empty `matching(...)`), so the list narrows live (`/mo` → `/model`) and normal chat input is untouched; `↑/↓` are rebound to `menu-complete`/`reverse-menu-complete` while a slash buffer is active (else history). It is installed only on a real TTY (dumb terminals degrade to plain Tab completion). Anything else is a chat turn: `runTurn` does `noteUserMessage → maybeCompress → kernel.chat(activeId, msg, sessionId) → renderStream → saveCurrent` (threading `sessionManager.getCurrentSessionId()` so each session persists to its own native `(userId,sessionId)` state slot). If the turn suspends on a `RequireUserConfirmEvent` (ASK-mode permission), the REPL prompts per tool (y/a/N), builds `List<ConfirmResult>`, and resumes via `kernel.chat(id, resumeMsg, sessionId)` carrying `Msg.METADATA_CONFIRM_RESULTS` (round-cap guarded). `renderStream` subscribes with a `CountDownLatch` and installs a SIGINT handler so **mid-turn Ctrl-C** calls `kernel.interruptCurrent()` + disposes the subscription and returns to the prompt (the process does NOT exit); the previous INT handler is restored in `finally`. At the prompt, idle Ctrl-C discards the line (`UserInterruptException`), Ctrl-D exits (`EndOfFileException`) — three states that don't cross-contaminate. Output is colored with **Jansi as a string builder only** — `AnsiConsole.systemInstall()` is intentionally NOT called (it double-wraps `System.out` and garbles output on Windows when JLine owns the terminal). See `cli/Ansi.java`. **Terminal requirement:** JLine needs a real console — use Windows Terminal / PowerShell / cmd; under git-bash/mintty stdin is not a real TTY, so run via `winpty` or use Windows Terminal.

**Sessions** (`SessionManager`, `av2` Phase 3): each conversation is isolated. Conversation history now persists **automatically via the native `AgentStateStore`** (`JsonFileAgentStateStore`, root `workspace/state/`) keyed by `(userId="pig", sessionId)` — the active session id is threaded per turn (`PigAgent.stream(Msg, sessionId)` → `RuntimeContext`), so the store auto-saves the slot at end of call. `SessionManager` keeps only pig's **metadata sidecar**: the lightweight `Session` record (name/timestamps/model binding/compression lineage) stored as `meta.json` by `FileSystemSessionRepository`, the per-session temp-memory file, and `current-session-id` restore. Switching = save-current → `ensureModel(...)` → point the temp-memory tier at the target → record the id (the native store loads/creates the conversation per turn; no `clearMemory`/`loadIfExists` handshake, no agent rebuild unless the model differs). `/session fork` copies the conversation via `PigAgent.copyConversation`. (`io.agentscope.core.session.Session`/`JsonSession` no longer exist in 2.0.) **Data note:** old 1.x `workspace/sessions/{id}/` conversation dirs are **not** auto-converted — a pre-existing session "starts fresh" if the native store has no slot, while its `meta.json` sidecar still reads, so it lists/switches correctly.

**Native two-layer memory (`pa-memory-native`).** Long-term memory is AgentScope 2.0's **native two-layer memory** — the self-built stack is **retired** (deleted: `CompositeLongTermMemory` two-tier + `FileSystemLongTermMemory` incl. its `MIN_TEXT_LENGTH=20` short-fact filter + `CachingLongTermMemory` + `EphemeralMemoryMiddleware` + the whole A4 `memory/extraction/*` pipeline; the per-session temp-memory tier is dropped). This **fixes the cross-session bug** (`bug/20260717-cross-session-memory`): the retired `record()` wrote only the session tier and the global tier was never auto-grown, so a fact stated in session A vanished after `/session new`. **How it works now:** `PigAgent.Builder.memory(MemoryConfig)` keeps the `HarnessAgent` vehicle's native memory ON (pig no longer `disableMemoryTools()`/`disableMemoryHooks()` when memory is enabled) — a per-turn **flush** hook extracts durable facts (LLM-driven, **no length filter**) into the daily ledger `memory/YYYY-MM-DD.md`, a background-throttled **consolidation** hook (`consolidation-min-gap-minutes`, default 30) merges+dedups them into the **workspace-level** `MEMORY.md`, and the native memory tools `memory_search`/`memory_get`/`memory_save`/`session_search`(+`session_list`/`session_history`) are exposed (classified in `ToolRiskClassifier` — searches/get READ_ONLY, `memory_save` WRITE). Both layers are workspace-level (not session-scoped) → durable facts are **cross-session by construction**. **Injection (OD2-A):** pig injects the consolidated `MEMORY.md` into the **system prompt** via a pig-owned `NativeMemoryContextMiddleware` (`onSystemPrompt`), NOT the native `WorkspaceContextMiddleware` — pig keeps `disableWorkspaceContext()` because that native middleware's guidance references native tool names (`read_file`/`grep`/`write_file`/…) pig doesn't register. `MEMORY.md` is stable within a session (consolidation is throttled) so the system prompt is prefix-cache-friendly turn-to-turn, changing only the once after a consolidation (accepted rare cache-miss). **Cheap model (OD8):** `MemoryConfig.model(...)` runs flush/consolidation on a lightweight model (config `memory.model-id`, e.g. Doubao lite; blank/unresolvable → the primary reasoning model). **`/memory on|off`** flips the top-level `memory-enabled` config flag then **rebuilds** the interactive + channel agents (same mechanism as an `/mcp` change) so off = native memory hooks/tools OFF + no `MEMORY.md` injection + no flush; on = all back. **Migration (OD9):** `MemoryMigration` does a one-time, idempotent, fault-tolerant copy of a legacy `workspace/context/memory.md` into `MEMORY.md` (with a `.bak` backup + `.migrated` marker; failure degrades to an empty new store, original preserved). Config block `memory` (`flush` always|never|throttled + `flush-throttle-minutes`, `consolidation-min-gap-minutes`, `consolidation-max-tokens`, `model-id`), all optional/default-safe. **Honest limits:** real flush/consolidation quality (the LLM extraction + dedup) needs a live-model `*IT`; the offline `CrossSessionMemoryTest` proves the structural fix by driving the native `memory_save`/`memory_search` tools across two session contexts (pure file IO, workspace-level). Change: `openspec/changes/pa-memory-native/`.

**Hybrid memory search (`hybrid-memory-search`, `io.pigagent.core.memory.search`, off by default).** Adds OpenClaw-style **hybrid BM25 + vector** ranking over the memory corpus (`MEMORY.md` + `memory/*.md` + `USER.md`), superseding the native keyword-only `memory_search` scan. `MemorySearchIndex` (the Strategy that ties it together) composes a `MemoryCorpusLoader` (chunks the three file types, fault-tolerant), a pure-Java `Bm25Index` (Okapi BM25 `k1=1.2`/`b=0.75`, shared `Tokenizer` with **CJK unigram+bigram** so a Chinese name matches — the corpus is often Chinese), a pluggable `VectorStore` (default `InMemoryVectorStore` = brute-force cosine, **no native deps**), and an optional `Embedder` behind a **mockable seam**; `HybridRanker` min-max-normalizes each component and blends `score = bm25Weight·BM25 + vectorWeight·cosine` (default **0.7/0.3**, configurable), dedups by doc id, top-K. Index build is **lazy + throttled** (rebuilt on corpus mtime change, `rebuild-throttle-seconds`). **Spike outcome (OD7):** AgentScope 2.0 has **no embedding Model API** and `sqlite-vec` is not offline-viable on this Windows/JDK, so the backend is **local pure-Java** — the vector layer sits behind the `Embedder` seam (offline tests use `DeterministicEmbedder`; the real `OpenAiCompatibleEmbedder` — a POST to an OpenAI-compatible `/embeddings` with a `StoredModel`'s creds, network behind an injectable `HttpPost` seam — has its request/response logic unit-tested offline but its **live round-trip is deferred to `/ls:itest`**). No embedder → graceful **BM25-only** degradation (never an error). **Tool:** `HybridMemorySearchTool` (`@Tool name="memory_search"`, READ_ONLY, `{"error"}` contract) — registered by `AgentBootstrap` only when `memory.search.hybrid-enabled`, at which point `PigAgent.Builder` detects the pig `memory_search` in the toolkit and calls `disableMemoryTools()` so it supersedes the native tools (native flush/consolidation **hooks** stay on → `MEMORY.md` still written; `memory_get`/`memory_save`/`session_search` are dropped in the hybrid path — a documented, off-by-default trade-off). Config block `memory.search` (`hybrid-enabled` default **false** → native keyword search unchanged; `bm25-weight`/`vector-weight`, `embedder-model-id`, `candidate-multiplier`, `min-score`, `top-k`, `rebuild-throttle-seconds`), all optional/default-safe. **Honest limits:** real embedding quality + the live `/embeddings` round-trip need a live-model `*IT`; the offline tests fully cover BM25 ranking, the hybrid blend (fake embedder), indexing all three files, dedup/top-K, throttled rebuild, and BM25-only degradation. **Shared retrieval primitive (`shared-retrieval`):** the generic ranker core — `SearchDocument` (the `{id,text}` contract), `Bm25Index` (now `index(List<? extends SearchDocument>)`), `HybridRanker`, `Tokenizer` — is lifted to the kernel package `io.pigagent.core.search` so memory retrieval, tool search (Tool-OS), and skill matching (Skills) consume **one** ranker (no scoring drift); `MemoryDocument implements SearchDocument` and the `MemorySearchIndex.search(query, topK) → List<MemoryDocument>` facade is unchanged (the vector/embedder classes stay in `memory.search`). Change: `openspec/changes/hybrid-memory-search/`, `openspec/changes/shared-retrieval-primitive/`.

**Memory retrieval injection (`memory-retrieval-injection`, `io.pigagent.core.memory.injection`, off by default).** RAG-style **on-demand** memory injection that supersedes the whole-`MEMORY.md`-into-system-prompt behavior of `NativeMemoryContextMiddleware` (which cost up to ~4000 tokens/turn). When `memory.injection.enabled`, injection is **split to preserve prefix-cache** (the load-bearing decision): `onSystemPrompt` injects only a stable, **query-independent pinned core** (a bounded `PinnedSelector` section of `MEMORY.md` — heading-marked, default heading `Pinned`, or a `head` fallback; degrades to empty when absent) so it stays byte-stable in the cached prefix; `onReasoning` injects the **query-aware top-K relevant facts** as a **trailing ephemeral** user-side `Msg` (rebuilt every step, never persisted, deduped against the pinned block) — **reusing the ephemeral trailing-`Msg` path** `LoopDetectionMiddleware` uses (the retired `EphemeralMemoryMiddleware` mechanism). Because `onSystemPrompt` has no query input, query-dependent content **structurally cannot** enter the cached system-prompt prefix — proven offline by the spike (`NativeMemoryContextMiddlewareTest`). Retrieval goes through the existing `MemorySearchIndex.search(query, topK)` stable facade (behind a narrow `MemoryRetriever` seam; **BM25-only** by default, zero embedder dependency, offline-testable — coordinated with R0 `shared-retrieval-primitive` which owns `MemorySearchIndex` internals). Threaded (nullable `MemoryInjection`) via `AgentFactory`/`AgentInstanceFactory` → `PigAgent.Builder.memoryInjection(...)` to the interactive/channel/peer tracks; only takes effect when native long-term memory is also on. Config block `memory.injection` (`enabled` default **false** → whole-`MEMORY.md` injection unchanged, byte-identical; `top-k`, `pinned.{source,heading,max-chars}`, `embedder-model-id`), all optional/default-safe. Scope is **declarative facts** only (procedural "how-to" stays in `SKILL.md`, boundary X3). **Honest limits:** real semantic recall (a real embedder) + prefix-cache hit-rate need a live-model `*IT`; BM25-only + the injection-split invariants are fully offline-covered. Change: `openspec/changes/memory-retrieval-injection/`.

**Consolidation quality layer (`memory-consolidation-quality`, `io.pigagent.core.memory.quality`, all opt-in / off by default).** A quality overlay on `pa-memory-native`'s flush→consolidation that adds three additive pieces without touching the default path (blank/off = byte-identical to today). **(1) Custom flush/consolidation prompts:** `AgentBootstrap.buildMemoryConfig` optionally calls the native `MemoryConfig.builder().flushPrompt(...)`/`.consolidationPrompt(...)` from config `memory.consolidation-quality.{flush-prompt,consolidation-prompt}`. Load-bearing constraint: the native `MemoryConsolidator` does `String.format(consolidationPrompt, maxTokens, maxChars)` (its default carries exactly two `%d`), so a custom consolidation prompt MUST pass the pure `ConsolidationPromptValidator` (**exactly two `%d`, no stray `%`**) — on failure pig logs + **keeps the native default** (fail-safe, so a malformed prompt never reaches/crashes the async background consolidation); a flush prompt is a plain SYSTEM prompt (non-blank check only, never `String.format`-ed). **(2) Semantic dedup curator:** when `memory.consolidation-quality.dedup.enabled`, a throttled, fault-tolerant `MemoryConsolidationCurator` (scheduled on `TaskScheduler`, mirroring `ProfileConsolidationService`) runs **after** native consolidation — splits `MEMORY.md` into fact units (`FactUnitSplitter`, keeping heading/layer markers verbatim), drops near-duplicates via the deterministic `SemanticDeduplicator` (union-find groups, longest representative kept), and atomically rewrites. Similarity **reuses the shared retrieval primitives**: `Vectors.cosine` over an `Embedder` (from the same `resolveEmbedder` seam as hybrid search / M-B) when configured, else self-normalized `io.pigagent.core.search.Bm25Index` (zero-dependency BM25 degradation); it drops, it never LLM-rewrites. **(3) `MEMORY.md` layer format contract** (`MemoryLayerFormat`, Pinned/General/Recent headings) — defined + read here (back-compatible: an unmarked legacy file is a single GENERAL layer) as the stable interface a future layered-decay capability (**M-C**) keys on; this spec only defines the contract, it does NOT implement decay. **Eval harness** (`memory/quality/eval/`: `MemoryEvalFixture` + `MemoryQualityAssertions` — key facts remembered / no near-duplicates / no key fact lost) proves the pipeline structure offline with a deterministic driver and is reusable by M-C; the real-model quality baseline is a deferred live `*IT` (`MemoryQualityIT`, default model 403). Config block `memory.consolidation-quality` (`flush-prompt`/`consolidation-prompt` blank, `dedup.{enabled default false, similarity-threshold 0.9, embedder-model-id, min-gap-minutes 60}`), all optional/default-safe. **Cross-deps:** M-C (layer contract + eval, sequential — M-D archives first), M-B (dedup embedder same-source, BM25 fallback so no hard dependency), skills line (declarative facts vs procedural `SKILL.md`). Change: `openspec/changes/consolidation-quality-and-eval/`.

**User profile (`user-profile`, `io.pigagent.core.profile`).** A **curated, structured user profile** `USER.md` (workspace root, config `user-profile.path`) — identity (name / how to address you), durable preferences (language, output style, tech preferences), working style — kept **distinct from `MEMORY.md`** (the general fact ledger): it's the Hermes "user modeling" idea as a simple local Markdown file (structured store / external Honcho = future). **Injection:** a pig-owned `UserProfileContextMiddleware` (`onSystemPrompt`, the profile **sibling** of `NativeMemoryContextMiddleware`) injects `USER.md` into the system prompt **before** `MEMORY.md` — `onSystemPrompt` is a left-to-right transformer, so with the profile middleware placed ahead of the memory one (which `PigAgent.build` appends last) the prompt becomes `base + USER + MEMORY` (profile before the fact ledger, Hermes-style; both frozen into the cacheable prefix). Injection is **bounded** (`max-chars`, truncated with a marker) and **credential-redacted** (a core `SecretRedactor`), byte-stable while `USER.md` is unchanged, and identity when the file is missing/blank. The middleware **self-gates** on `user-profile.enabled` (read live) → disabled = the prompt is untouched (today's behavior), no per-agent rebuild; one stateless instance is shared across interactive/channel/peer tracks. **Maintenance, two paths:** (1) an `updateProfile` `@Tool` (`pig-agent-tools`, classified **WRITE** in `ToolRiskClassifier`, `{"error"}` contract, `ToolAvailability`-gated on `user-profile.enabled` so it's hidden from the schema when off) sets/merges **one** profile field **deterministically** (replace a same-named `- **Field**: value` line, else append; no model call) — the agent writes a confirmed preference immediately (e.g. "call me X"/"always reply in Chinese"); the `UserProfileStore` is the single read/write/merge point (bounded read, `SecretRedactor` on write, atomic-ish move, fault-tolerant). (2) An **optional background consolidation** (`user-profile.consolidation`, **default off**): a throttled, fault-tolerant `ProfileConsolidationService` distills durable identity/preferences from `MEMORY.md` into a deduped `USER.md` via a **cheap model** (`consolidation.model-id` → `memory.model-id` → primary) behind the mockable `ProfileDistiller` seam (`ModelProfileDistiller` = throwaway agent, mirroring `CompressionService.ModelSummarizer`); when enabled it runs on the existing `TaskScheduler` at the `min-gap` cadence (the service self-throttles too). Config block `user-profile` (`enabled` default **true**, `path`, `max-chars`, `consolidation.{enabled default false, min-gap-minutes, model-id}`), all optional/default-safe. First run starts empty (no seed); `USER.md` is workspace-level so a field set via `updateProfile` in session A is injected in session B (cross-session by construction, mirroring the memory fix). **Honest limits:** real distillation quality (LLM extraction/dedup + seeding identity from a `MEMORY.md` name) needs a live-model `*IT`; offline tests cover the store merge, bounded+redacted injection, the mockable consolidation seam (throttle/fault-tolerance), and cross-session visibility. **Context compression / context engineering** (`CompressionService` + `compression/ContextEngineer`, capability `context-memory-efficiency`, change `context-engineering`; **DELIBERATELY kept as a differentiator (A5)**, so `PigAgent` `disableCompaction()`s the native harness compaction rather than adopt it): operates only on the in-memory conversation — read/rewritten through the `ConversationMemory` adapter (a `Memory` view over the native `AgentState.contextMutable()`) — never on persisted history or memory. The model call stays behind a mockable `CompressionService.Summarizer` seam (a throwaway agent on the current model). When an estimated token budget (config `compression`) is exceeded it rewrites the conversation through a **structured context-engineering pipeline** (design-pattern-oriented; `CompressionService` still owns the `Memory` mutation + lineage, `ContextEngineer` is the pure, model-free-except-the-seam brain): **(1) three-tier budget** — a pure `ContextBudget`/`BudgetRatios` value object deterministically splits the window into `pinned`/`recent-verbatim`/`summarized` tiers (ratios normalized, tiers sum to total); the `summarized` tier is the recursion threshold (`pinned`/`recent` are allocated + surfaced by `/compress status`, not yet hard caps). **(2) recursive summarization** — `RecursiveSummarizer` (Strategy) re-summarizes the summary (summary-of-summaries) while it still exceeds the summarized budget, bounded by `max-summary-depth`; the model call stays behind the existing `CompressionService.Summarizer` **mockable seam** (offline-testable). **(3) importance retention** — a pure `ImportanceScorer`/`HeuristicImportanceScorer` (Strategy) keeps high-value older turns (user decisions/corrections/errors) verbatim rather than summarizing them. **(4) verbatim protection** — a pure `VerbatimGuard` detects code fences, commands, IDs/hashes and long exact quotes and keeps those whole messages verbatim (MUST NOT be summarized). **(5) consistency check + safe fallback** — after building a candidate, `ConsistencyChecker` verifies high-importance/protected content survived; on failure it falls back to a **safer, less-aggressive profile** (`EngineeringOptions.safe()`: verbatim + importance forced on, recursion off) and re-checks, and if that still fails keeps the original context uncompressed — never silently dropping critical context. Config lives under `compression` (all optional/default-safe: `keep-recent`, `recursive-summary`, `max-summary-depth`, `importance-retention`, `verbatim-protection`, `consistency-check`, `pinned/recent/summarized-ratio`); **defaults reproduce the prior "summarize-old, keep-recent" behavior on small conversations** (nothing pulled verbatim, no recursion, no protected spans), so existing compression tests stay green. `/compress now|status|off|on`. **Compression derives a session lineage (record-only, no UI)** (`compression-lineage`): after a successful compression, an optional `CompressionLineageRecorder` (core seam; implemented by `SessionLineageWriter` in the session module, wired in `AgentBootstrap`) writes provenance into the session metadata — `Session.lineageId` (stable across the compression chain, assigned on first compression) + `parentSessionId` (the just-superseded pre-compression state), via `Session.withCompressionLineage()`. It is lightweight (same session id, no new session dir, no snapshot content) and **independent of the compression core**: it runs only after memory is rewritten and any failure is logged and swallowed, so it never breaks compression. Old `meta.json` without lineage fields reads back as no-parent (fault-tolerant). Queryable via `SessionManager.lineageOf(id)` for a future TUI; nothing is displayed yet.

**Dynamic MCP management** (`McpManager` + `JsonMcpStore`): MCP servers are CRUD-managed at runtime and persist to `workspace/mcp.json` (the source of truth, keyed by name). On first run, legacy `application.yaml`'s `mcp.servers` are imported once into `mcp.json`. `McpManager` holds the `Toolkit` plus a `name→McpClientWrapper` map and registers/unregisters MCP tools live. Concurrency uses a **fine-grained lock (E1)**: network/process connect + `listTools` run *outside* the lock; only the short collision-check + `registerMcpClient` + `map.put` critical section is `synchronized(this)`. Tool namespace is **flat (D-NS)**: adding a server whose tool name collides with an already-registered tool is refused. Operate via `/mcp list|add|remove|edit|enable|disable|test` (operator-facing, full trust — may add stdio servers). The agent can self-manage MCP via the `McpTool` (`@Tool`), gated by the **D-SEC** security door (`mcp.agent-management`): `allow-add`/`allow-remove` default **off**; when add is enabled, only URL servers whose host is in `allowed-hosts`, after human confirmation, are accepted (never stdio/command); `list`/`test` are always allowed; `env`/`headers` are redacted in tool output to avoid credential echo.

**Tool availability gating** (`io.pigagent.tool.availability`): the **first-line filter** deciding whether a tool is even visible to the model, applied when the toolkit is assembled in `AgentBootstrap` (`ToolAvailabilityGate.applyTo(toolkit, builtins)`) — orthogonal to and stacked *before* the permission veto (availability = visibility; permissions = may-a-visible-tool-run). A built-in tool MAY implement the optional, **non-invasive** `ToolAvailability` interface (`availabilityToolNames()` + `checkAvailability() → Availability`) to declare a runtime precondition; tools that don't implement it are always available (backward compatible). Unavailable tools are `removeTool`-ed from the shared toolkit so they never enter the model schema (prevents hallucinated calls, saves tokens); a check that throws is **fail-safe → unavailable** and never blocks other tools. The gate returns an immutable `ToolAvailabilityReport` (list of `(toolName, reason)`) carried on `Services`/`ReplContext` and shown by `/status` — reasons name the missing prerequisite only (e.g. `BRAVE_API_KEY not set`), **never a credential value**. Example: `BraveWebSearchTool` gates `webSearch` on `BRAVE_API_KEY`. Availability is evaluated once at bootstrap (no runtime re-eval / hot schema swap; MCP tools' availability is their connection state, per the existing `McpManager`).

**Deferred tools + `tool_search` (`deferred-tools`, `io.pigagent.tool.deferred`, default smart-on / backward-safe).** A *dynamic, on-demand* visibility layer stacked on top of the (static) availability gate — borrowed from deerflow's `DeferredToolFilterMiddleware`: large/rarely-used tools (especially as MCP servers grow) are kept OUT of the model's **initial** tool schema to save every-turn prompt tokens, and the model discovers + enables them on demand via a built-in **`tool_search`** (`READ_ONLY`, in `ToolRiskClassifier`). **Mechanism = AgentScope's native tool groups** (the `Toolkit` group API — `registration().group(...)` / `updateToolGroups` — is preserved in 2.0): a tool parked in an **inactive** group is excluded from `Toolkit.getToolSchemas()` (`ToolSchemaProvider`) *and* rejected at call time (`ToolExecutor.executeCore` → "Unauthorized tool call"), so **defer = inactive group; reveal = activate the group** (`updateToolGroups(...,true)`, a pure flag flip — the tool object is never removed/re-registered, so execution wiring, the `GuardedAgentTool` wrapper and MCP `mcpClientName` are all untouched). This is strictly cleaner than remove/re-add, whose re-registration would drop `mcpClientName` and break `McpManager.removeMcpClient`. `DeferredToolPlanner` (pure Strategy) decides what to defer from config `tools.deferred` (`enabled`, explicit `tools` list, and an `auto-defer-mcp` + `threshold` rule that defers all MCP tools once the total tool count exceeds the threshold, default 25); `DeferredToolGate` applies it — built-in/plugin tools go into a per-tool inactive group (`deferred__<tool>`, re-registering their current `AgentTool`), MCP tools are deferred by deactivating the `mcp:<server>` group they were registered into **at attach time** (`McpManager.setToolGroupNamer` → `registration().mcpClient(...).group(g)`, MCP-safe). `DeferredToolRegistry` holds each deferred tool's name+description+keywords+group; `tool_search` ranks a query against them with the **shared kernel retrieval primitives** (`io.pigagent.core.search`: `Bm25Index` + `HybridRanker` + CJK `Tokenizer`, BM25-only via an empty vector map — the same ranker `memory_search` uses, so tool/memory search never drift; each deferred tool projected onto a `ToolDocument` `id`=name/`text`=name+description+keywords), reveals the matches (activates their group; MCP reveal is per-server), and returns their names+descriptions (empty/no-match → a helpful hint listing searchable names). Wired in `AgentBootstrap`: when enabled, `tool_search` is registered **before** `ToolContractGuard.install` (so it's guarded and never re-registers MCP tools) with the same registry the gate later populates after MCP attaches. **Default is "smart-on" (`enabled=true`) with a backward-safe threshold gate (T2):** the planner only defers when the tool count exceeds `threshold` (25); when the resulting plan is **empty** (small toolset, no explicit list), `AgentBootstrap.applyDeferral` **removes `tool_search`** and does no grouping so the initial schema is **byte-identical to `enabled=false`** (MCP tools are grouped into ACTIVE, schema-neutral groups) — a small-toolset user sees no change, MCP-dense users get the token savings automatically; `enabled=false` fully disables. **Reveal across `Toolkit.copy()` (T2 fix):** because a copy has INDEPENDENT group active-state, a reveal is broadcast to every live toolkit via a kernel `RevealTargets` (`io.pigagent.core.tool`) — the base + peer copies register in `AgentBootstrap`, subagent child copies register via `PigAgent.Builder.revealTargets` — so a `tool_search` reveal takes effect on whichever copy the current agent runs. **Limitations:** evaluated once at bootstrap (hot-added MCP servers stay visible until restart, like the availability gate); MCP reveal granularity is per-server.

**Tool permissions** (`io.pigagent.tool.permission`, gated by `permissions` config; `av2` Phase 2/4 — now the **native `PermissionEngine`**, no self-built hook). Pig's global **mode** — `plan`, `ask` (default), `auto`, `bypass` — plus its risk classification (`ToolRiskClassifier`: READ_ONLY/WRITE/EXEC/NETWORK/MCP_ADMIN; unknown → EXEC fail-safe; `tool-overrides` can reclassify) are **mapped by `PermissionContextFactory` onto a native `io.agentscope.core.permission.PermissionContextState`** and installed via `PigAgent.Builder.permissionContext(...)` → `HarnessAgent`/`ReActAgent`. Base-mode mapping: `plan→EXPLORE`, `ask→DEFAULT`, `auto→ACCEPT_EDITS`, `bypass→BYPASS`; non-interactive (channel/autonomous, no confirmer) → `DONT_ASK` base + per-tool ASK→DENY (**fail-closed**). Per-tool rules (`PermissionRule` keyed by tool name, behavior `ALLOW/DENY/ASK/PASSTHROUGH`) come from the unchanged `PermissionPolicy` table; native precedence is **deny > ask > allow > tool-check > mode-default**. Enforcement is a **gate before execution**: the engine returns `DENY` and the ReAct loop feeds a `ToolResultState.DENIED` back so the model continues (no sentinel tool anymore — `PermissionDeniedTool`/`ToolPermissionHook` are deleted). **ASK → HITL** surfaces as a native `RequireUserConfirmEvent`; `AgentRepl` prompts (y/a/N) and resumes with `List<ConfirmResult>` via `Msg.METADATA_CONFIRM_RESULTS`; `a`(always) persists to `permissions.allowlist`. **EXPLORE (plan) read-only enforcement keys on `AgentTool.isReadOnly()`** — pig's read-only `@Tool` methods declare `readOnly=true` (`readFile`/`listDirectory`/`listSkills`/`loadSkill`/`tool_search`/`showChecklist`/compute tools/mcp list+test) so plan permits reads and denies every mutating tool. **P0 (security, `av2` Phase 6b):** the native engine is only consulted when the resolved tool `instanceof ToolBase` (a non-`ToolBase` tool is auto-ALLOWed); pig's `ToolContractGuard` wraps every tool in `GuardedAgentTool`, which used to implement only `AgentTool` → **every guarded tool bypassed the engine in production**. Fixed by making `GuardedAgentTool extends ToolBase` (delegating `checkPermissions`/`matchRule`/`generateSuggestions`), so enforcement actually runs on the real toolkit. **Command-granular allowlist (`allowlist.commands`, M-1):** `executeCommand` is wrapped in a `CommandPermissionTool extends ToolBase` whose `checkPermissions` returns ALLOW when the command's normalized first token (`CommandKeys.of`) is allowlisted, else PASSTHROUGH → mode default (and `PermissionContextFactory` emits no ASK rule for it so the tool check governs). MCP_ADMIN is delegated to the existing **D-SEC** door. Operate via `/permission status|mode|channel-mode|allow|revoke|reset|list` (`/permission mode` calls native `setPermissionMode` on the active session slot). Default `ask` changes prior behavior (was effectively bypass) — `/permission mode bypass` restores it. Channels run through a **separate channel agent** whose context uses `channel-mode` (default `auto`, non-interactive fail-closed); `ModelManager.attachChannel` rebuilds it on model switch. Live-model proof: `PermissionEnforcementIT`/`FullLinkAgentIT` (10/10 on real Doubao, incl. the P0 runtime regression guard).

**Tool return contract (`tool-json-contract`, `io.pigagent.tool.contract`):** built-in `@Tool` tools follow a uniform result contract — success returns the tool's normal output, **failure returns a canonical `{"error":"<reason>"}`** (build it with `ToolErrors.message(...)`), never an exception, and the reason is credential-redacted (`CredentialSanitizer`, aligned with the model/mcp "never echo a key/token" convention). A **dispatch-layer safety net** backs this up: `ToolContractGuard.install(toolkit)` (called in `AgentBootstrap`) wraps every built-in tool in a `GuardedAgentTool` decorator so *any* exception a tool lets escape — sync throw, failing `Mono`, or null — becomes a canonical error result (logged at `warn` with the stack, sanitized) instead of aborting the turn. Two layers (tool self-guard + dispatch guard) mean either alone stops an exception from propagating. **`GuardedAgentTool extends ToolBase`** (`av2` Phase 6b P0 — see permissions): it snapshots the delegate's name/description/parameters/`readOnly` and forwards the native permission hooks (`checkPermissions`/`matchRule`/`generateSuggestions`), so a guarded tool is still a `ToolBase` and the `PermissionEngine` actually gates it. The guard is installed **before MCP servers attach** so it never re-registers live MCP-server tools (which AgentScope manages by `mcpClientName`); `Toolkit.copy()` per-agent toolkits inherit the guarded built-in tools.

**Tool egress sandbox & credential hardening (`tool-sandbox-and-secrets`, capabilities `tool-sandbox` + `credential-hardening`):** a third orthogonal tool guard, stacked *after* availability (visibility) and permissions (may-run) — it bounds what a *visible, permitted* tool can reach, and hardens credential handling. **File egress:** `FileSystemTools` `readFile`/`writeFile` refuse the workspace credential files (`models.json`/`mcp.json` + `.bak`) — this is a **credential-file blacklist, NOT a workspace sandbox** (this is a coding agent; arbitrary project files stay accessible). Matching normalizes to the resolved real path (`toRealPath`, else `toAbsolutePath().normalize()`), remembering both forms, so `../` traversal and symlinks are caught. **Web egress (SSRF):** `SmartWebFetchTool.fetchUrl` runs `SsrfGuard.checkBlocked` first — it resolves the host via `InetAddress.getAllByName` and blocks if **any** resolved IP is loopback/any-local/link-local(`169.254`)/site-local-private/IPv6-ULA/multicast (judging the **resolved IP**, not the literal host, defeats decimal-IP/`[::1]`/DNS-points-inward), rejects non-`http(s)` schemes, keeps `Redirect.NEVER`, and honors an optional `tools.web.allowed-hosts` allowlist. Blocked tools return the canonical `{"error"}` (no exception, no internal IP echoed). Both guards get their deps (`workspaceRoot`, `webAllowedHosts`) via `ToolContext` from `AgentBootstrap`; **safety defaults need no config** (blacklist auto-on from the workspace root, SSRF always blocks private ranges). **Credential hygiene:** API-key / sensitive-value entry is masked (REPL `/model add|edit` and `/mcp add|edit` sensitive keys via JLine `readLine(prompt,'*')`; `OnboardingWizard` via `Console.readPassword`, degrading to a visible read + one-time warning with no console); `JsonModelStore`/`JsonMcpStore` restrict the written file to `0600` on POSIX (`restrictToOwner`, ignored on non-POSIX). Credentials still stored plaintext (rely on `0600` + directory perms — do not use on a shared host). Resolves the review's P0 #1–4 and MCP security follow-ups M-1/M-2.

**Command-execution sandbox (`exec-sandbox`, P1 of the sandbox system).** A fourth orthogonal guard specific to `ShellTools.executeCommand` — the "constrained-run" layer, stacked *after* the permission veto (may-run): permissions decide *whether* a command runs, this decides *how constrained* it is while it runs (a permitted `rm -rf /` is still blocked here; a normal command only gets the runtime bounds). Two collaborators live in `io.pigagent.tool.sandbox`: a config-backed immutable value object `SandboxPolicy` and a Strategy `CommandGuard` that is the single home of the denylist / output-cap / env-scrub logic (not scattered in `executeCommand`). Four constraints: **(1) output cap** — `capOutput(InputStream)` does a *bounded* read (default 200 KB), draining/discarding the remainder to avoid pipe-deadlock and appending a truncation marker (replaces the OOM-prone `readAllBytes()`); **(2) configurable timeout** (default 30s, was hardcoded); **(3) a conservative catastrophic-command denylist** — a compiled-in floor (root/home deletes, `mkfs`/`format`/`diskpart`, pipe-to-shell installs, fork bombs, `shutdown`/`reboot`, `dd of=/dev/…`, `chmod -R 777 /`) that config `exec.denylist` can only *extend* (never weaken); classification is **two-pass, three-tier, most-severe-wins** (`block` > `warn` > `pass`) to resist operator bypass — structural patterns scan the whole normalized command, then it splits on shell operators (`; && || | &`, *quote-aware*) and matches single-command rules per sub-command, so `echo ok && rm -rf /` is caught while `git commit -m "a && b"` is not; cheap input validation (empty / >10 000 chars / NUL byte) runs first; **(4) env credential scrubbing** (default on) — strips credential-bearing vars (`*_KEY`/`*TOKEN*`/`*SECRET*`/`*PASSWORD*`/…) from the child so a command can't `echo $ANTHROPIC_API_KEY`, keeping PATH/HOME/etc; plus an optional `exec.working-dir`. Config lives under `sandbox.exec` in `application.yaml` (all optional, default-safe; a malformed cap/timeout clamps to the default). Wired like the other tool guards: `AgentBootstrap` builds a `SandboxPolicy` from config and injects it via `ToolContext` → `ShellToolsProvider` → `ShellTools`; no config = conservative defaults. Blocked commands return the canonical `{"error":"blocked: <category>"}` (reason names the category only, never the command; the audit-log line redacts the command via `CredentialSanitizer` + truncates). **Honest limitations:** this is a best-effort in-process boundary, **not OS-level isolation** (no seccomp/namespaces/containers — that's P3) and the denylist is a "resist foot-guns / prompt-injected disasters" filter, **not** a barrier against a determined adversary (base64/alias/variable tricks defeat any regex denylist); autonomous/channel-specific tightening is P4. **Middle "warn" tier (D12, `sandbox-warn-tier`):** the classifier is now three-tier — a conservative built-in **warn set** (`pip install`, `apt`/`apt-get install`, `sudo`/`su`, non-root `chmod 777`, `PATH=` reassignment, `npm install -g`; extendable via `sandbox.exec.warnlist`, carried on `SandboxPolicy.extraWarnPatterns`) flags medium-risk-but-legitimate commands. A warn-matching command (that isn't also a block) **runs normally** but `ShellTools` appends a `⚠️ Warning: <category>` note to the tool result so the model sees the risk; `CommandGuard.classify` reuses the same two-pass structure (`checkDenied` is now a block-only view of it, so the block/pass contract and every prior test are unchanged). Warn is **purely additive** — most-severe-wins keeps block strictly ahead of warn, and normal dev commands (mvn/git/npm run/ls) stay silent. Same best-effort caveat as the denylist (regex, not an adversarial boundary).

**Tool-call loop detection (`loop-detection`, `io.pigagent.core.loop`).** A fifth orthogonal safety net catching the "same action, over and over" failure mode (re-`readFile` the same file, re-run the same failed command, retry after a wall) that burns tokens and never converges — a mode the veto/availability/contract/sandbox guards don't cover. Borrowed from deerflow's `LoopDetectionMiddleware`. **Strategy + Adapter design:** a pure, offline-tested `LoopDetector` keeps a sliding window (default 20) of recent tool-call *signatures* and maps the current signature's repeat count to a `LoopDecision` — `WARN` at ≥ `warn-threshold` (3), `STOP` at ≥ `stop-threshold` (5); the window evicts the oldest when full and bad config is clamped (`window/warn ≥ 1`, `stop ≥ warn`). How a call folds to a signature is a swappable `ToolCallSignatureStrategy`; the default **buckets `readFile` by 200-line ranges** (`readFile|<path>|#<startLine/200>` — so re-reading nearly the same region counts as a repeat; a paramless read of one path collapses to bucket 0) and **hashes full args for `writeFile`/edits/everything else** (`toolName|sha256(canonical(input))`, key-order-independent — so writing different content is never a repeat). The thin adapter `LoopDetectionMiddleware` (`av2` Phase 5a, a `MiddlewareBase`; placed **before** the memory middleware so its `onReasoning` counts the raw conversation before memory injection — mirroring the old hook priority 10<50) plugs the detector into stages: on `onActing` it observes the pending `ToolUseBlock` (skipping the sentinels in its ignore set — its own `loopDetected` — and bypassing entirely when disabled), and on `STOP` **reuses the sentinel-rewrite** — building a **new** `ActingInput` that rewrites the block to the read-only `LoopDetectedTool` (`loopDetected`, in `pig-agent-tools`) so the real tool never runs and the model is told to stop and answer (deliberately chosen over hand-built DENIED events — it reuses the framework's tool-result wiring); on `WARN` it queues a nudge injected on the next `onReasoning` as a trailing user-side `Msg` — **reusing the ephemeral injection path** of `EphemeralMemoryMiddleware` (rebuilt each step, never persisted). It **resets the detector per turn** by watching the USER-message count in the reasoning input (change ⇒ new turn / session switch ⇒ `reset()`), so counts never leak across turns. Config `loop-detection` (`enabled` default true, `window-size` 20, `warn-threshold` 3, `stop-threshold` 5) is all-optional/default-safe/back-compatible; `enabled: false` fully bypasses. `AgentBootstrap` gives the interactive and channel agents each their own detector instance (autonomous one-shot agents get a fresh window per run, so they self-reset). Change: `openspec/changes/archive/2026-07-15-loop-detection/`.

The legacy `model:` block in YAML is kept for display/back-compat but `models.json` is the source of truth; likewise the legacy `mcp.servers` block is imported once then `mcp.json` is the source of truth.

**Model retry + interrupt (`av2` Phase 5a — native, self-built decorators deleted).** Retry is now the framework's: `PigAgent.Builder.maxRetries(int)` + `.fallbackModel(...)` → `ReActAgent.Builder.maxRetries/.fallbackModel`, applied **inside the model extension impls** on a fresh `model.stream` HTTP call within one agent invocation (a `Retry.backoff(...).jitter(...).filter(RETRYABLE_ERRORS)`). Native `ExecutionConfig.RETRYABLE_ERRORS` classifies transient (**429** + 5xx via `isRetryableHttpStatus`, `TimeoutException`, `IOException`) vs permanent (4xx/auth) — a **superset** of pig's old classifier, so `RetryingModel`/`RetryPolicy`/`TransientErrorClassifier` are all **deleted**. `AgentBootstrap` maps config `model.retry`: `enabled` → `maxRetries = max(1, max-retries)`; `disabled` → `maxRetries = 1`. **Interrupt** is native `ReActAgent.interrupt(RuntimeContext)`; pig keeps its frontend-facing `InterruptController`/`TurnHandle` (in `io.pigagent.core.interrupt`) — `AgentKernel.chat` registers a `TurnHandle` whose interrupt drives `PigAgent.interrupt(sessionId)` and wraps the stream in `takeUntilOther(...)` so the frontend regains control immediately (`InterruptibleModel` decorator deleted). **Trade-offs vs the old decorators:** the inline `[retry k/N]` notice is gone (native has no per-retry callback); native interrupt is *cooperative* (reclaimed at reasoning-step boundaries / the model-layer HTTP timeout, bounded), not instant. `NativeRetryWiringTest` asserts the config reaches the native `ModelConfig`; the real transient-vs-permanent behavior is a live-model IT.

**Digital employee (autonomous agents)** (`io.pigagent.core.agent.runner`): an `AgentSpec` with a non-blank `schedule` (a cron expression) is autonomous — `PigAgentCli` registers it with the generalized `TaskScheduler.schedule(id, TaskSchedule, Runnable)` (real 5-field cron via cron-utils, e.g. `0 2 * * *`), which fires `AgentRunner.run(spec)`. `AgentRunner` builds an **isolated one-shot agent** (never the active instance; independent memory), runs the spec's `mandate` unattended, and writes a three-section morning report (`我做了 / 我发现 / 等你决定`) to `workspace/reports/{date}/{id}.md` (`FileReportWriter`). Safety: non-interactive → native `DONT_ASK` base + per-tool ASK→DENY (fail-closed); the agent's `commandAllowlist` (merged into `permissions.allowlist.commands`, honored by `CommandPermissionTool`) lets it run a few safe commands (e.g. `mvn test`); everything else dangerous is denied by the native `PermissionEngine`, and `DeniedActionRecorder` scans the finished conversation for `ToolResultBlock`s with `ToolResultState.DENIED` (post-hoc, since native permission has no build-time denial callback) to surface them under「等你决定」. Timeout is **best-effort** (background thread + `Future.get`/`cancel`; native interrupt is cooperative, so it marks TIMEOUT and reports). Reentrancy-guarded; every run (success/failure/timeout) writes a report and updates `lastRunAt`. Operate via `/agent run <id>` (run now) and `/agent report`. Sample: `docs/examples/nightwatch.md`.

**Tasks** persist as Markdown at `workspace/tasks/{date}/{id}.md` (recurring under `tasks/recurring/`); `TaskScheduler` runs ONCE/CRON/DELAYED schedules on a `ScheduledExecutorService`.

**Autonomous guardrails** (`autonomous-guardrails`): three production safety nets. (1) `maxIters` now bounds **every** agent via `PigAgent.Builder.maxIters` (→ native `HarnessAgent`/`ReActAgent` maxIters; only applied when `> 0`, preserved across model switches) — interactive/channel take `agent.max-iters` (default **40**), per-agent/autonomous take `AgentSpec.maxIters` (default **10**, conservative for unattended runs). (2) Task `.md` persistence is **lossless** — the Schedule line encodes `ONCE` / `CRON:<expr>` / `DELAYED:<seconds>` plus `Created`/`Updated` timestamps + description, so CRON/DELAYED tasks survive a restart and are re-scheduled by `scheduleAll` — and **fault-tolerant**: a corrupt/incomplete task file is skipped with a warn (never crashes `findAll`/startup `scheduleAll`), and old type-only Schedule lines degrade to `ONCE`. (3) `PigAgentConfig` ignores unknown fields (`@JsonIgnoreProperties(ignoreUnknown = true)`) so config schema drift no longer fails the whole load and reverts every setting to defaults.

**Native subagents (delegation; `av2` Phase 6a/6b, `subagents.enabled` default ON).** Distinct from **peer** agents (above): a *subagent* is a transient **child** the active agent delegates a subtask to via the native tools `agent_spawn`/`agent_send`/`agent_list` + `task_output`/`task_cancel`/`task_list` (built-in `general-purpose` child + `workspace/subagents/<id>.md` declarations whose front-matter mirrors `AgentSpec`). Enabled on the **interactive tracks only** (default + `/agent` peers) by `PigAgent.Builder.subagents(true)` (which stops the vehicle's `disableSubagents()`); channel/autonomous stay off. A peer `AgentSpec` can *also* be surfaced as a spawnable child via `AgentSpecSubagentMapper` — "both a switchable peer AND delegable" without conflating them. **Parent-permission inheritance (pig-injected, closing a 2.0.0 gap):** `SubagentDeclaration.inheritParentPermissions` is **inert** in 2.0.0 (no harness class reads it — javap-verified; a naive enable would be a permission-escape), so pig registers a custom `HarnessAgent.Builder.subagentFactory(...)` (last-put-wins over the native factory) that builds each **leaf** child (`disableSubagents`) under a fail-closed context derived by `SubagentPermissions.deriveChildContext(parent)` — parent **DENY rules copied verbatim**, inherited ASK downgraded to DENY, EXPLORE/BYPASS preserved, everything else → DONT_ASK. Because the child's tools are the parent's guarded `ToolBase`s (the P0 fix), its `PermissionEngine` actually gates them (proven: a parent-DENYed tool cannot run in the spawned child). Synchronous child events forward onto the parent's `streamEvents` tagged with `AgentEvent.getSource()` (e.g. `main/reviewer`); `AgentRepl` renders them dim + nested + source-labeled via `render/SubagentEventRenderer` (credential-redacted). Background (`timeout_seconds=0`) tasks surface their result as a `<system-reminder>` the parent reasons over. Change: `av2` §14/§15.

**Plan Mode (`plan-mode`, native, default OFF).** AgentScope 2.0's "think read-only → write `PLAN.md` → HITL-approve → execute". `PigAgent.Builder.planMode(PlanModeSettings)` calls the vehicle's `enablePlanMode()` + `planFileDirectory(<plan-dir>)` (default `plans`) + `allowShellInPlanMode`, installing the plan trio (`plan_enter`/`plan_write`/`plan_exit`) + `PlanModeMiddleware`. Read-only enforcement keys on `AgentTool.isReadOnly()` (the same flags EXPLORE uses) → **zero per-tool change**; the plan is written to `<workspace>/<plan-dir>/PLAN.md`. The model's `plan_exit` returns `PermissionDecision.ask(...)` → a `RequireUserConfirmEvent` handled by the existing HITL confirm/resume loop (approve → execute; reject → stay). Operate via `/plan enter|exit|status` (`PlanCommand`; `enter` gated on `plan-mode.enabled`). **Orthogonal to `/permission mode plan` (EXPLORE):** EXPLORE is a permission-engine read-only toggle; native Plan Mode is a structured plan-file + HITL flow whose read-only is enforced independently by the middleware (holds even under BYPASS) — entering/exiting one does not change the other. Default OFF because it installs a middleware whose `onSystemPrompt` appends a plan hint (breaks byte-stability). Wired into the interactive + per-agent tracks only (channel/autonomous have no confirmer). A `StatusLine` `⏸ PLAN` badge shows when the current session is plan-active. Subagents can't be spawned while plan-active (`agent_spawn` is non-read-only → denied). For pig, `allow-shell` is effectively a no-op (it whitelists the native `execute`; pig uses its own non-read-only `executeCommand`). Change: `av2` §16.

**Tool-result eviction (`tools.result-eviction`, native, default ON — the one capability pig lacked).** A single tool result over `threshold` chars (default **80000**) is spooled to `<workspace>/<dir>` (default `/large_tool_results`) and the retained conversation is rewritten to a read-back placeholder (+ a `preview-chars` preview), so a huge file read / command output can't bloat future turns. `AgentBootstrap.buildEvictionConfig` builds a native `ToolResultEvictionConfig` from config and threads it (+ the workspace root) via `AgentFactory`/`AgentInstanceFactory` → `PigAgent.Builder.toolResultEviction(...)`/`.workspace(...)` to every build path; `enabled:false` → the vehicle's `disableToolResultEviction()`. Change: `av2` §13.

**Gateway channel kernel (`channel-gateway`, native, opt-in default OFF).** The deferred Phase-6c: adopt AgentScope 2.0's native `Gateway`/`ChatUiChannel` (in `agentscope-harness`) **behind** pig's channel seam. `GatewayChannelKernel` (`pig-agent-channel`, `io.pigagent.channel.gateway`) is built over a pig `HarnessAgent` via `mainAgent.channel(ChatUiChannel.create())` — giving native routing + per-session fair queuing + the auto-wired subagent bridge that makes `expose_to_user` functional; all threaded by `SendOptions(userId, sessionId, agentId)`, consistent with the Phase-3 `(userId,sessionId)` state slots. `ChannelAgentBridge` takes an **optional** `GatewayChannelKernel`: with it, inbound routes through `kernel.sendStream(...)`; without it (default) the prior direct `agentHolder.get().stream(...)` path — byte-identical default behavior. **Native platform adapters** (DingTalk/Feishu/GitHub/GitLab/WeCom via `agentscope-extensions-channel-*`) are **opt-in behind `channels.<id>.native: true`** and loaded **reflectively** by `NativeChannelFactory` (`NativeChannelType` holds the FQCN/props convention) — the artifacts aren't in the offline repo, so absent → graceful fallback to pig's custom channel. Slack/Webhook/Stdin + `StrategyHttpChannel` (DingTalk/Feishu webhooks) stay pig custom. `expose_to_user`: a subagent spawned with `expose_to_user=true` emits a `SubagentExposedEvent` and is reachable via `GatewayChannelKernel.sendToSubagent(...)`; the outreach send-seam can retarget onto a native `Channel.deliver(...)` via `GatewayOutboundChannel`. **Honest limits:** native adapters can't be exercised offline (need real endpoints + the extension jars); a model-switch doesn't auto-rebind the gateway yet; the REPL doesn't yet address exposed subagents. Change: `av2` §17.

**Proactive outreach + notifications (`proactive-outreach`, off by default).** The assistant can **initiate contact** — on a trigger it sends an *unsolicited* message to the user through a channel (daily briefing, reminder, decision request, alert), not just reply when addressed. Design-pattern-oriented and **framework-neutral** (pig-owned seams): it fills 2.0's native channel-gateway "no proactive push" gap — the `send` seam is kept thin, and `GatewayOutboundChannel` already retargets it onto a native `Channel.deliver(...)` when the Gateway kernel is enabled, with the outreach logic unchanged. Layers: **(1) outbound capability** — an optional `OutboundChannel.send(recipient, Notification)` a channel MAY implement (inbound-only channels don't; graceful degradation); `StrategyHttpChannel` (DingTalk/Feishu) implements it by rendering + dispatching over its custom-robot webhook (real, best-effort — `ChannelStrategy.send` is fire-and-forget so it returns `true` on dispatch; Slack/Webhook/Stdin stay inbound-only). **(2) value type + service seam** (framework-neutral, `pig-agent-core.outreach`) — immutable `Notification` (`NotificationType`/`Severity`/title/body/optional `OutreachAction`/target channel+recipient/dedup key) + the `NotificationService` seam (`notify(Notification) → NotificationResult`, never throws); `ChannelNotificationService` (`pig-agent-channel`) routes by channel id via a lookup function to the right `OutboundChannel` (no outbound → a helpful `NO_CHANNEL` result), after the guardrail. **(3) anti-nag guardrails** (pure `OutreachPolicy` value object + stateful, clock-injectable `OutreachGate`) — rate-limit + de-dup + quiet-hours, yielding `OutreachDecision`; **URGENT bypasses quiet-hours + rate-limit** (a 24h assistant must be able to raise an alert), **de-dup always applies** (never resend the same key within the window). **(4) triggers (Strategy)** — *scheduled* (`ScheduledOutreach` armed via the `OutreachScheduler` seam, which the CLI adapts to the existing `TaskScheduler`; e.g. a 09:00 briefing) and *event/agent-initiated* (`NotificationReportWriter` pushes the digital-employee morning report via `CompositeReportWriter` alongside `FileReportWriter`; the agent pings the user through the `notifyUser` tool). **(5) `notifyUser` `@Tool`** (`pig-agent-tools`) — classified `NETWORK` in `ToolRiskClassifier` (governed by permissions) and `ToolAvailability`-gated on `outreach.enabled` (hidden from the model schema when off); success/suppressed/failed map to a success line / a plain status line / the canonical `{"error"}` — the recipient is **never echoed**. **(6) `/notify status|test`** operator command (`/notify status` shows config but never the recipient value). Wired in `AgentBootstrap` (`OutreachPolicy` read live from config → `OutreachGate` → `ChannelNotificationService` over an initially-empty `ChannelRegistry` that `PigAgentCli` populates after channels start, so channel lookup is lazy at notify time), injected into `ToolContext` + `Services`. Config `outreach` (`enabled` default **false** → `notifyUser` hidden, no briefing/report-push, `/notify` shows disabled; zero behavior change; `channel`/`recipient`/`quiet-hours`/`rate-limit`/`dedup-window-minutes`/`briefing`/`report-push`), all optional/default-safe. Recipient tokens are kept out of logs/tool output/command echo (`CredentialSanitizer`). **Limitations:** only DingTalk/Feishu have real (best-effort) outbound; guardrail state is in-memory (reset on restart); real delivery confirmation + real-channel round-trips need a real-channel `*IT`. Change: `openspec/changes/proactive-outreach/`.

## Conventions

- **Immutability is enforced.** Domain types (`Task`, `Session`, `StoredModel`, `ProviderCredentials`, config events) are records; mutate via `withXxx()` copy methods. See `.claude/rules/common/coding-style.md`.
- File-backed repositories are **fault-tolerant**: a single corrupt file (bad `meta.json` / `models.json`) is skipped or backed up, never crashes the listing. Follow that pattern for new persistence.
- Tests use **JUnit 5 + Mockito + AssertJ**, AAA structure (test classes in `config`, `core`, `task`, `workspace`, `session`, `model`, and `cli`).
- Async/reactive APIs from AgentScope use Project Reactor (`Mono`/`Flux`); streaming consumes the native `Flux<AgentEvent>` (from `streamEvents`) and dispatches on the concrete event subtype (`TextBlockDeltaEvent`, `ToolResult*Event`, `RequireUserConfirmEvent`, …) — the 1.x `Flux<Event>`/`EventType` filtering is gone.
- **Logging is SLF4J + Logback** (`logging-framework`). Every class logs via `private static final Logger log = LoggerFactory.getLogger(X.class)` with parameterized messages (`log.info("... {}", x)`); do NOT use `System.out`/`System.err` for diagnostics (`out`→`info`, `err`→`warn`/`error(msg, throwable)`). The SLF4J **API** is the only logging dep in library modules; the **backend** (`logback-classic`, managed at `logback.version` in the parent) lives only in the entry module `pig-agent-cli`, configured by `pig-agent-cli/src/main/resources/logback.xml` (console + rolling file → `~/.pig-agent/workspace/logs/pig-agent.log`; `io.pigagent`=INFO, noisy libs=WARN). Tests use `logback-test.xml` (WARN, console-only); the DashScope SDK's bundled `slf4j-simple` is excluded in `pig-agent-providers` to keep Logback the sole binding. **Genuinely interactive terminal I/O is NOT logging and stays on the console**: the `OnboardingWizard` prompts, the startup ASCII banner, and REPL output via `Ansi.println(terminal, …)`.

## AI 开发流水线（`/ls:*`）

> **强制规约**：实现任何需求/特性/修复 MUST 走此流水线，不得跳阶段/越人工门/自行拍板拆分。硬性规则见 [`.claude/rules/common/ls-pipeline.md`](.claude/rules/common/ls-pipeline.md)。

一条半自动的 AI 开发流水线，把既有能力串成标准流程（命令定义在 `.claude/commands/ls/`，复用 `/opsx:*` + `.claude/rules/common/`，不重造）。

```
需求澄清 → 特性分支(feat/bug/docs/opt) → spec 设计 → [编码⇄单测 内环] → 集成测试 外环 → openspec 归档
```

| 命令 | 阶段 | 门 | 职责 |
|------|------|-----|------|
| `/ls:clarify` | 需求澄清 + 拆分 + 建分支 | ⏸ 人工 | AskUserQuestion 问清需求；**大需求拆成多个可独立上线的 spec（人工审拆分）**；每个 spec 从 `origin/main` 拉 `<type>/<name>` 分支（可并行） |
| `/ls:spec` | spec 设计 | ⏸ 人工审批 | 委托 `/opsx:propose` 生成 proposal/design/tasks + delta spec，`openspec validate --strict` |
| `/ls:code` | 编码⇄单测（**内环**） | 自动 | 逐 task TDD：测试→实现→`mvn test`→勾选；组后 `mvn compile` |
| `/ls:itest` | 集成测试（**外环**） | 自动 | 跑 `*IT` 真模型测试；失败回喂 `/ls:code`；连续 3 轮无进展升级人工 |
| `/ls:archive` | openspec 归档 | ⏸ 人工确认 | 委托 `/opsx:archive`：同步主 spec + 移到 `changes/archive/` |
| `/ls:status` | 进度汇报 | 只读 | 跨 澄清/设计/规格/任务 维度统计所有活跃 spec（多 spec 并行视图 + 卡点） |
| `/ls:dev` | 总控 | 半自动 | 端到端串联五阶段，尊重上述人工门 |

**两层 loop engine**：内环 = 编码⇄单测（`/ls:code`，快、离线）；外环 = 任务→内环→集成测试（`/ls:itest`，慢、真模型），失败回环至绿。**半自动**：澄清/spec/归档人工把门，编码+测试自动推进。**多 spec**：大需求在 `/ls:clarify` 拆成多个可独立上线的 spec（拆分须人工审），各自 `feat/<name>` 分支——**依赖允许时并行，否则按依赖顺序推进**（后者在前者归档后才细化 tasks），`/ls:status` 汇总进度。**分支前缀**：`feat`/`bug`/`docs`/`opt`（`bug/` 分支的提交信息仍用 conventional-commit `fix:`）。完整指南 + 实战复盘见 `docs/ai-dev-pipeline.md`；规约基座见 `.claude/rules/common/development-workflow.md`。
