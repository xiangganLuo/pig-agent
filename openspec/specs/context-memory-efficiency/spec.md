# context-memory-efficiency Specification

## Purpose
内核上下文压缩热路径的效率优化：让上下文压缩的 token 估算与摘要都 tool-aware（覆盖 tool 调用入参与 tool 返回结果，而非仅纯文本），使压缩触发反映真实上下文规模、让摘要保留关键 tool 输出——不改压缩触发阈值/保留策略。（历史注：本能力原含「回合内记忆检索缓存」（`CachingLongTermMemory` 装饰器），随 `pa-memory-native` 采用 2.0 原生两层记忆、退役 pig 自建 `LongTermMemory` 栈而消解。）
## Requirements
### Requirement: token 估算计入全部内容块

上下文压缩的 token 估算 SHALL 覆盖每条消息的全部内容块——文本、tool 调用入参、以及 tool 返回结果载荷——而非仅计文本。估算 MAY 沿用 `~字符数/4` 的近似启发式，但 MUST 作用于消息的完整序列化内容，使压缩触发反映真实上下文规模。

#### Scenario: 大 tool 结果显著抬高估算
- **WHEN** 对一条携带大体量 tool 返回结果的消息估算 token
- **THEN** 其估算值显著高于仅按文本计的估算（tool 结果被计入，不再被漏掉）

#### Scenario: 纯文本估算不受影响
- **WHEN** 对不含 tool 内容的纯文本消息估算 token
- **THEN** 估算与按文本计基本一致

### Requirement: 摘要保留 tool 调用与结果

当压缩摘要较早回合时，喂给摘要模型的文本 SHALL 纳入 tool 调用与 tool 返回结果的内容（可紧凑、按块截断），使摘要能够保留重要的 tool 输出，而非仅摘要纯文本。摘要 SHALL 在**摘要层预算**（见「三层 token 预算分配」的 summarized 档）内进行，且被判定为受保护逐字的内容（见「代码/精确文本逐字保护」）与被判定为高重要度的旧回合（见「重要度选择性保留」）MUST NOT 被喂入摘要、而是逐字保留。

#### Scenario: 摘要输入含 tool 结果
- **WHEN** 待摘要的回合中包含携带 tool 返回结果的消息
- **THEN** 交给摘要模型的文本包含该 tool 结果的载荷内容

#### Scenario: 巨型 tool 结果按块截断
- **WHEN** 某条消息的单个 tool 结果块极大
- **THEN** 该块在摘要输入中被截断到上限，避免撑爆摘要器自身的上下文

#### Scenario: 受保护/高重要度内容不进摘要
- **WHEN** 待压缩的较早回合中既有普通闲聊、也有受保护逐字内容或高重要度回合
- **THEN** 只有普通闲聊被喂入摘要模型，受保护逐字内容与高重要度回合被逐字保留、不被摘要改写

### Requirement: 三层 token 预算分配

系统 SHALL 提供一个纯计算的三层预算值对象，把上下文窗口按可配置比例确定性地切分为三档——**pinned（system + 必留关键事实）**、**recent（最近逐字窗口）**、**summarized（可摘要的较旧内容）**。切分 MUST 确定（同输入同输出、不依赖模型），且三档之和 MUST 恒等于总预算。比例未归一化时 MUST 先归一化再切分。summarized 档预算 SHALL 作为递归摘要的触发阈值；pinned 与 recent 档预算为对应内容预留额度并被上报（状态展示）。

#### Scenario: 按比例确定性切分
- **WHEN** 给定总预算与已归一的三档比例
- **THEN** 三档 token 数按比例确定性得出，且三档之和等于总预算

#### Scenario: 比例未归一化先归一化
- **WHEN** 传入的三档比例之和不为 1（如 1:1:2）
- **THEN** 先按和归一化（得 0.25:0.25:0.5）再切分，结果确定

#### Scenario: 汇总层预算约束摘要
- **WHEN** 计算出 summarized 档预算
- **THEN** 该预算被用作递归摘要「是否需要再摘要」的判据阈值

### Requirement: 递归摘要（限深）

当可摘要内容经一次摘要后其估算仍超过摘要层预算时，系统 SHALL 对摘要再做摘要（summary-of-summaries）以进一步收敛，且 MUST 受最大递归深度约束。模型摘要调用 SHALL 集中在一个可替换/可 mock 的缝（复用既有摘要接口），使递归逻辑可离线单测。关闭递归或最大深度为 0 时，SHALL 退化为单层摘要（既有行为）。

#### Scenario: 摘要仍超预算触发再摘要
- **WHEN** 一次摘要后其估算 token 仍超过摘要层预算，且未达最大深度
- **THEN** 对该摘要再做一次摘要以继续收敛

#### Scenario: 达到最大深度即停止
- **WHEN** 递归摘要已达到配置的最大深度
- **THEN** 不再继续递归，返回当前摘要（记录所用深度）

#### Scenario: 预算内不递归
- **WHEN** 一次摘要后其估算已在摘要层预算内
- **THEN** 不发生再摘要，仅一层摘要（与既有行为一致）

### Requirement: 重要度选择性保留

系统 SHALL 通过一个纯启发式的重要度评分策略给回合打分，使**用户决策、纠正、报错**等高价值旧回合的分数高于寒暄闲聊。压缩时高重要度的较旧回合 SHALL 被逐字保留（即使较旧），低重要度的较旧回合 SHALL 优先进入摘要。该策略 SHALL 可通过配置关闭，关闭后退回「较旧内容一律摘要」的既有行为。

#### Scenario: 决策/报错高于闲聊
- **WHEN** 分别对一条用户决策/纠正/报错消息与一条寒暄闲聊消息评分
- **THEN** 前者的重要度分数高于后者

#### Scenario: 高重要度旧回合逐字保留
- **WHEN** 较旧回合中包含高重要度消息且重要度保留开启
- **THEN** 该高重要度消息被逐字保留在压缩结果中，而非被摘要

#### Scenario: 关闭重要度保留退回既有行为
- **WHEN** 重要度保留被配置关闭
- **THEN** 所有较旧回合一律进入摘要，行为与引入本能力前一致

### Requirement: 代码/精确文本逐字保护

代码块（围栏 / 行内）、命令行、ID/哈希（长十六进制、SHA、UUID）、精确引用文本等**不可改写**内容 MUST NOT 被（递归）摘要。系统 SHALL 通过一个纯粹的逐字守卫识别这些受保护内容；命中的消息 SHALL 被整条逐字保留、不喂摘要模型。守卫 SHALL 保守（宁可漏放，不可把普通闲聊误判为受保护）。

#### Scenario: 含代码块的消息不被摘要
- **WHEN** 某条较旧消息包含围栏代码块
- **THEN** 该消息被识别为受保护并逐字保留，不被喂入摘要模型

#### Scenario: 命令/哈希/ID 被识别为受保护
- **WHEN** 某条消息含命令行、长哈希或 UUID
- **THEN** 逐字守卫将其识别为受保护内容

#### Scenario: 普通闲聊不被误判
- **WHEN** 某条消息是普通自然语言闲聊、不含代码/命令/哈希/精确引用
- **THEN** 逐字守卫不将其判为受保护

### Requirement: 一致性校验与安全回退

一次压缩产出候选结果后，系统 SHALL 做一次轻量一致性校验，验证 pinned/高重要度消息与受保护逐字片段是否仍存在于结果中。校验不通过时，系统 SHALL 回退到更安全（更不激进）的行为——强制逐字保护与重要度保留、并停用递归摘要——重建结果并再次校验；若仍不通过，SHALL 保持原上下文不压缩。系统 MUST NOT 在关键上下文丢失时静默产出压缩结果，且回退 SHALL 记日志（不泄露受保护内容原文）。

#### Scenario: 校验通过则提交增强结果
- **WHEN** 增强压缩的候选结果通过一致性校验
- **THEN** 采用该增强结果

#### Scenario: 校验发现关键事实丢失则安全回退
- **WHEN** 候选结果缺失某个应逐字保留的 pinned/高重要度事实或受保护片段
- **THEN** 系统回退到更安全行为（逐字保护 + 重要度保留、停用递归），把该关键事实逐字保住，并记日志

#### Scenario: 回退仍无法保住则保持原上下文
- **WHEN** 即便更安全行为也无法通过一致性校验
- **THEN** 系统保持原上下文不压缩，绝不静默丢弃关键上下文

### Requirement: 默认安全配置与既有行为等价

三层预算比例、递归开关与最大深度、重要度/逐字/一致性开关、最近保留条数等新增配置项 MUST 全部可选、缺省安全，坏值 SHALL 被容错钳制到缺省。缺省配置下，对小规模纯文本对话的压缩结果 SHALL 与引入本能力前一致（单段摘要 + 最近若干条逐字），使既有压缩测试保持通过。

#### Scenario: 缺省配置下小对话压缩结果与既有一致
- **WHEN** 在缺省配置下对一段小规模纯文本对话触发压缩
- **THEN** 结果为「一段摘要 + 最近保留的若干条逐字」，与引入本能力前的结果一致

#### Scenario: 坏配置容错钳制
- **WHEN** 配置给出非法值（如负的最大深度、和为 0 的比例）
- **THEN** 系统钳制到缺省值而非崩溃
