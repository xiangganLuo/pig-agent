## ADDED Requirements

### Requirement: 嵌入模型为模型层一等存储类别

系统 SHALL 把「嵌入模型」作为模型层的一等存储类别：每个保存的模型配置 MUST 携带一个类别判别（`kind`：`CHAT` 或 `EMBEDDING`，默认 `CHAT`），使一个 OpenAI 兼容 `/embeddings` 端点及其凭据（`baseUrl`/`apiKey`/`modelName`）可作为独立实体被存储。系统 SHALL 维护一个**独立于默认聊天模型**的默认嵌入模型指针。类别与默认嵌入指针 MUST 与聊天模型一样持久化到 `models.json`。系统 MUST 向后兼容既有 `models.json`：缺失 `kind` 字段的条目 MUST 读回为 `CHAT`，缺失默认嵌入指针 MUST 读回为「无」，且既有默认聊天模型语义 MUST NOT 改变。

#### Scenario: 保存一个嵌入模型
- **WHEN** 用户保存一个类别为 `EMBEDDING` 的模型配置（含 protocol/凭据/模型名）
- **THEN** 该配置以 `EMBEDDING` 类别持久化到 `models.json`，可被单独列出与选择，且不改变任何已保存的聊天模型

#### Scenario: 独立的默认嵌入模型指针
- **WHEN** 用户把某个嵌入模型设为默认嵌入模型
- **THEN** 系统记录一个独立于默认聊天模型的默认嵌入模型指针，二者互不影响

#### Scenario: 旧 models.json 向后兼容
- **WHEN** 读取一个不含 `kind` 字段、也不含默认嵌入指针的既有 `models.json`
- **THEN** 每个条目读回为 `CHAT`、默认嵌入指针为「无」，聊天模型的加载与默认选择行为逐字节等于本能力引入前

#### Scenario: 删除默认嵌入模型回落
- **WHEN** 用户删除当前被设为默认嵌入模型的那个模型
- **THEN** 默认嵌入指针被清空（回落到「无嵌入模型」），系统不崩溃

### Requirement: 嵌入模型的管理与首次配置 UX

`/model` 命令 SHALL 支持嵌入模型：用户 SHALL 能新增一个嵌入模型（选择类别为嵌入 → 选择协议 → 输入凭据/base URL/模型名），列表 SHALL 标注每个模型的类别，用户 SHALL 能把某个嵌入模型设为默认嵌入模型。首次配置向导（onboarding）SHALL 提供一个**可选、可跳过**的嵌入模型步骤；向导 MUST 仍要求至少一个可用的聊天模型（不可跳过），跳过嵌入步骤时行为 MUST 等于本能力引入前。嵌入模型限于经 OpenAI 兼容 `/embeddings` 契约访问的协议。

#### Scenario: 经 /model 新增嵌入模型
- **WHEN** 用户经 `/model add` 选择嵌入类别并完成协议/凭据/模型名输入
- **THEN** 系统先做连通性测试、通过后保存为一个嵌入模型；`/model list` 中它被标注为嵌入类别

#### Scenario: onboarding 跳过嵌入步骤
- **WHEN** 首次配置向导在配好聊天模型后询问是否配置嵌入模型，用户选择跳过
- **THEN** 系统仅保存聊天模型，不保存任何嵌入模型，后续行为等于本能力引入前（BM25-only 检索）

#### Scenario: 设置默认嵌入模型
- **WHEN** 存在至少一个嵌入模型，用户将其设为默认嵌入模型
- **THEN** 后续在未显式指定嵌入模型时，系统解析该默认嵌入模型作为嵌入器来源

### Requirement: 嵌入模型凭据硬化

嵌入模型的凭据处理 MUST 沿用聊天模型的凭据硬化约定：API key 输入 MUST 掩码（交互式终端不回显、不进滚动缓冲），`models.json` 落盘 MUST 在 POSIX 平台限制为属主读写（`0600`），任何错误信息、日志与命令回显 MUST NOT 包含凭据明文。

#### Scenario: 掩码输入嵌入模型凭据
- **WHEN** 用户在 `/model add` 或首次配置向导中输入嵌入模型的 API key
- **THEN** 输入被掩码、不回显到终端

#### Scenario: 连通性测试失败不泄露凭据
- **WHEN** 嵌入模型连通性测试失败
- **THEN** 返回的错误信息为友好、已脱敏的原因，MUST NOT 包含 API key 明文

### Requirement: /embeddings 连通性测试

系统 SHALL 在保存或激活一个嵌入模型前对其做连通性测试，与聊天模型的连通性测试同构：测试 MUST 按模型类别分派——聊天模型走既有聊天探针，嵌入模型走一次对其 OpenAI 兼容 `/embeddings` 端点的探针（用该模型的凭据构建嵌入器并请求一次嵌入）。测试 MUST 有界超时、MUST 把失败映射为友好、已脱敏的结果（与聊天连通性测试同一映射），MUST NOT 抛出未处理异常。真实的 `/embeddings` 网络往返验证延后到集成测试（`/ls:itest`）；探针的成功/失败/超时映射 MUST 可离线单测（经可注入的嵌入/HTTP seam）。

#### Scenario: 嵌入模型连通性测试成功
- **WHEN** 对一个凭据/端点有效的嵌入模型做连通性测试
- **THEN** 系统请求一次嵌入并得到向量，测试返回成功

#### Scenario: 嵌入模型连通性测试失败映射
- **WHEN** 嵌入模型的端点不可达或凭据无效
- **THEN** 测试返回失败，附一个友好、已脱敏的原因，不抛出未处理异常

#### Scenario: 连通性测试有界超时
- **WHEN** 嵌入模型端点长时间无响应
- **THEN** 测试在有界超时内返回一个清晰的超时原因，不无限阻塞

### Requirement: 嵌入模型解析为嵌入器

系统 SHALL 把一个嵌入 `StoredModel` 解析为一个可用的嵌入器（对 OpenAI 兼容 `/embeddings` 端点发起请求），解析顺序 SHALL 为：显式配置的嵌入模型 id（若已设且可解析）→ 否则默认嵌入模型指针（若存在且可解析）→ 否则「无嵌入器」。解析出的嵌入器 MUST 复用既有的可注入 HTTP seam（使网络逻辑离线可测）。当嵌入模型 id/指针为空或不可解析时，解析 MUST 容错地返回「无嵌入器」（不抛异常），使检索层安全降级。为向后兼容，从一个 `StoredModel` 的凭据构建嵌入器 MUST NOT 硬性要求其类别为 `EMBEDDING`（既有指向聊天模型的嵌入配置仍工作）。

#### Scenario: 显式配置的嵌入模型被解析
- **WHEN** 配置了一个可解析的嵌入模型 id
- **THEN** 系统用其凭据构建一个针对其 `/embeddings` 端点的嵌入器（经可注入 HTTP seam）

#### Scenario: 回落到默认嵌入模型指针
- **WHEN** 未显式配置嵌入模型 id，但存在一个可解析的默认嵌入模型
- **THEN** 系统解析该默认嵌入模型作为嵌入器来源

#### Scenario: 不可解析时容错降级
- **WHEN** 嵌入模型 id/指针为空、或指向一个已不存在的模型、或构建时异常
- **THEN** 系统返回「无嵌入器」、记录告警（不含凭据明文）、不抛异常

### Requirement: 默认无嵌入模型时零回归

当**未配置任何嵌入模型**（无嵌入类别条目、无默认嵌入指针、无显式嵌入模型配置）时，嵌入器解析 MUST 返回「无嵌入器」，检索层 MUST 退化为仅 BM25，行为 MUST 逐字节等于本能力引入前。启用嵌入模型 MUST 为**可选**——不配置时聊天模型的存储/UX/测试/解析全部不变。本能力 MUST NOT 改变默认检索路径（把 BM25-only 升级为混合属后续能力，不在本能力内）。

#### Scenario: 未配置嵌入模型即今日行为
- **WHEN** 未配置任何嵌入模型
- **THEN** 嵌入器解析返回「无嵌入器」，检索层仅 BM25，行为逐字节等于本能力引入前

#### Scenario: 嵌入模型为可选、不影响聊天模型
- **WHEN** 用户从不新增嵌入模型
- **THEN** 聊天模型的新增/列表/切换/编辑/删除与连通性测试行为完全不变

#### Scenario: 本能力不翻默认检索路径
- **WHEN** 已配置一个嵌入模型
- **THEN** 本能力仅**提供**解析出的嵌入器供检索层消费，默认检索路径本身是否升级为混合 MUST NOT 由本能力改变
