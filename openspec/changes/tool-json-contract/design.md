## Context

内建工具以 `@Tool`/`@ToolParam` 方法暴露，返回值交给 AgentScope 作为 tool result。目前没有统一约束「工具错误必须以规范结果返回」，异常可能穿透到 agent 循环。凭据脱敏在 model/mcp 已有约定，工具错误消息也应遵守。

## Goals / Non-Goals

**Goals:**
- 工具成功/失败均返回规范结果，错误走 `{"error"}`。
- 分发层双层兜底，异常不穿透。
- 错误消息不泄露凭据。

**Non-Goals:**
- 不改权限 veto / 可用性门控等其它维度。
- 不重写工具的业务逻辑，只规范其返回/错误形态与兜底。

## Decisions

- **D1 — 契约表达**：约定工具错误返回统一结构（如返回含 `error` 字段的规范结果），提供一个错误结果构造 helper 供工具复用，减少各工具手写。
- **D2 — 双层兜底位置**：在工具调用/分发的公共路径包 try/catch（既有 hook/adapter 层或统一调用包装），把任何逸出的异常转成规范错误结果。两层含义：工具内自守 + 分发层兜底，任一层缺失都不至于让异常穿透。
- **D3 — 凭据安全**：错误消息构造经一个「脱敏」步骤（复用/对齐 model/mcp 的脱敏约定），确保不回显 key/token。
- **D4 — 渐进接入**：优先在分发层加统一兜底（覆盖面最大、最快消除穿透风险）；工具侧契约作为规范逐步对齐（新工具遵循，存量按需改）。

## Risks / Trade-offs

- **R1 — 兜底掩盖真实错误**：统一兜底可能把本应暴露的 bug 变成温和错误结果。→ 兜底同时记录 warn/error 日志（含堆栈，但脱敏），保证可诊断。
- **R2 — 契约迁移成本**：存量工具逐个对齐有成本。→ D4 渐进策略：先分发层兜底保证安全底线，再逐步规范工具侧。
- **R3 — 与 AgentScope 返回约定的耦合**：需确认 AgentScope 对 tool result 的类型期望，规范结果形态与之兼容。
